## Architecture (deliberate separation)
- USER affect: UserAffectModel.inferred_emotion is a free string
  (explicit/self-report + understanding.inferred_emotion).
- Monday INTERNAL: EmotionalState enum on AdvancedEmotionalEngine.current_emotion;
  get_state exposes it as emotion/current_emotion. Driven by PAD from appraisal
  monday_pad_delta — NOT by casting user-affect strings into the enum.
- EmotionalState.RELIEVED present: True
- EmotionalState.EXHAUSTED present: True
- EmotionalState.UNKNOWN present: False (user-affect 'unknown' is string-only)
- Overlap of label names (relieved/exhausted) is deliberate breadth for both sides;
  fields remain independent. User-affect strings are never pushed into Monday's enum.

## Fixes in this pass
1) success event maps USER emotion to 'unknown' (not neutral-without-evidence,
   and still never auto proud/happy from success alone). Explicit self-report wins.
2) negation_affected and contrast_affected are independent flags;
   contrast supersession alone does NOT set negated=True.

## Remaining issues
- Basic embeddings still propose noisy candidates; unused when disagreeing / below support bar.
- Sentence-transformers unavailable here; paraphrase-only cues lean on AppraisalEngine.
- Monday INTERNAL after a single utterance is PAD/RNG-sensitive (varies across runs);
  separation invariant is field independence, not a fixed Monday label per sentence.
- No dual secondary-emotion field: after-but current-state supersedes earlier named emotion.
